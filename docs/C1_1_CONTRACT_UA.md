# Coffeo C1.1 — контракт API v1

## Джерело істини

`src/contracts/v1/schema.ts` містить Zod-схеми та виведені TypeScript DTO. `npm run contract:generate` генерує `openapi/coffeo.v1.json`; `npm run contract:check` перевіряє, що документ точно відповідає джерелу. Фронтенд зберігає копію цієї схеми у `lib/contracts/v1/schema.ts`, SHA-256 її вмісту та commit API у `contract-lock.json`. Оновлення контракту потребує зміни обох репозиторіїв і обох CI.

Версійні маршрути API мають префікс `/v1`, BFF — `/api/v1`. Стара `/products` та решта legacy-маршрутів поки працюють. Інтерфейс магазину переводитиметься на v1 окремими квитками; він ще використовує старий контракт. BFF допускає лише перелічені в контракті шляхи, перевіряє запити та відповіді, передає cookie і не кешує персональні дані. Секрет внутрішнього API надсилає лише серверний BFF.

## Реалізовані операції

| Метод і шлях                  | Поведінка                                                                                                                                           |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/products`            | Активні товари; `q`, `category`, `roast`, `sort`, `page`, `pageSize`; `pageSize` 1–50, стабільне сортування з `id` як другим ключем.                |
| `GET /v1/products/:id`        | Активний товар або 404.                                                                                                                             |
| `GET /v1/products/slug/:slug` | Активний товар за slug або 404.                                                                                                                     |
| `GET /v1/profile/me`          | Профіль власника або `data: null`; вимагає сесію.                                                                                                   |
| `PATCH /v1/profile/me`        | Тільки дозволені поля профілю; `null` очищує поле, відсутність поля залишає його без змін. `userId`, `role` та інші невідомі поля — 400 без запису. |

Відповідь об'єкта: `{ "data": ... }`; список: `{ "data": [...], "page": { "number": 1, "size": 20, "total": 0 } }`. Помилка: `{ "error": { "code": "...", "message": "...", "fieldErrors": {}, "requestId": "..." } }`. Сервер не записує тіло запиту або персональні дані в нові журнали.

## Зарезервовані операції та межі C1.1

`POST /v1/cart/items` і `POST /v1/orders` перевіряють суворі схеми, після чого повертають 501 `FEATURE_NOT_AVAILABLE`. Сьогодні немає таблиці Cart з `revision`, стійкої quote, ідемпотентного checkout та потрібних інваріантів запасів. Вигадувати їх у відповіді або використовувати старий маршрут кошика з клієнтською ціною не можна. `POST /v1/admin/products` теж повертає 501 після перевірки прав; повноцінний запис товару належить C2. Ці маршрути видимі в OpenAPI як зарезервовані, а не як працездатні операції продажу. Auth v1 та решта операцій із майбутньої таблиці §3 технічного плану не оголошені працездатними; legacy auth поки діє.

## Гроші й валюта

Поля `priceMinor`, `unitPriceMinor`, `subtotalMinor`, `discountMinor`, `shippingMinor`, `totalMinor` — безпечні цілі числа найменших одиниць відповідної валюти. Для наявних двозначних Decimal(10,2) API перетворює десятковий **текст** через BigInt; проміжного `Number(price) * 100` немає. Всі DTO несуть `currency` із збереженого запису. Історичні `USD` не перейменовуються на `UAH`; міграція та політика нових гривневих продажів належать пізнішим квиткам. `memberDiscountPercent` та `scaScore` лишаються точними десятковими рядками, не копійками.

## Перевірки

API: `npm run contract:check`, `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run build`, `npm run db:validate`, `npm test` на ізольованій PostgreSQL. Web: `npm run contract:check`, `npm run test:contracts`, `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run build`. API CI застосовує міграції тільки до своєї одноразової PostgreSQL. Фікстури використовують `example.test` і синтетичні записи; production не служить тестовою БД.
