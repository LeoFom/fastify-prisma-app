# C0.4 — правила Coffeo та автоматичні перевірки

Дата: 24.11.2026. Scope: AGENTS, lint/format tooling, CI та узгоджені документи. Схема БД, auth/checkout поведінка, зовнішні інтеграції й release-політика C0.5 цим квитком не змінюються.

## Зміни

- API має Coffeo-specific `AGENTS.md`; web має ті самі архітектурні обмеження після незміненого Next-generated блоку. Правила описують BFF-only, server secrets, Customer registration, окремий bootstrap, test DB, межі квитків і фактичне приймання.
- API: ESLint flat config із рекомендованими JS/TypeScript правилами. Перевіряються помилки й невикористаний код; generated Prisma, dist та node_modules виключені. Видалено невикористані імпорти й перейменовано невикористані параметри без зміни HTTP-поведінки.
- `no-explicit-any` наразі вимкнено в API: контрактний борг усувається відповідними C1 DTO-квитками. Lint не є твердженням про повну типобезпечність. TypeScript strict і typecheck залишаються обов'язковими.
- API та web використовують однакові Prettier 3.10.1, конфіг і format gate. ESLint 9.39.5 збережено як сумісну з чинним frontend лінійку; npm попереджає про завершення підтримки ESLint 9. Це відомий tooling lifecycle debt; перехід на наступну major потребує перевірки Next plugins, а не `audit fix --force`.
- CI API додає lint, format:check та явний typecheck до чинних build, DB validation/migrations і інтеграційних тестів. CI web додає format:check і test:tooling до lint, typecheck, build. Обидва зберігають npm audit та lockfile install.
- README ведуть до актуальних аудиту й плану; PROJECT/BUGS/ROADMAP та пов'язані старі описи позначені historical. План містить майбутні роботи, а не твердження про завершені функції.
- Рішення власника про історичні доступи записані в C0.3: Nodemailer видалено за повідомленням власника; MongoDB вирішено видалити; інші старі доступи відкладені. Це не незалежна перевірка провайдерів.

## Поступове форматування

`npm run format:check` перевіряє доступні Prettier файли Git inventory, включно з новими неігнорованими файлами. Ігноруються залежності, build/generated, lockfiles, env та старий каталог скілів. Він не звертається до БД і не читає ігноровані секрети.

`.format-baseline.json` — одноразовий перелік незмінених файлів з попереднього dev, які ще не проходять Prettier. Хеш SHA-256 обчислений після нормалізації CRLF → LF. Нові файли та змінений вміст старих файлів мають пройти Prettier; baseline не дозволяє нову помилку й не приховує parse error. Після редагування файлу використовувати `npx --no-install prettier --write шлях/до/файлу`, а не оновлювати baseline. Не форматувати весь репозиторій без окремої потреби.

Початкові entries звірені з blob SHA віддаленого dev до C0.4; змінені/нові файли цього квитка до baseline не включені. Gate не гарантує стиль усієї legacy-бази: незмінений борг показується лічильником у результаті.

Обидва repo мають шість `test:tooling` перевірок: новий коректний файл; новий некоректний; незмінений legacy; змінений legacy; CRLF checkout; синтаксична помилка навіть із відповідним hash. Це тести інструмента, не всього магазину. API `npm test` включає їх разом із DB-тестами.

Нових міграцій немає. Локально native migrate deploy не перезапускався; CI застосовує повну чинну історію на disposable PostgreSQL. Перевірки не записували дані в production. Browser E2E повторно не запускався: UI та HTTP-контракти не змінювалися.

Відомі попередження: pg SSL-mode alias і query concurrency deprecation у локальних DB-тестах; Next images.domains і workspace-root warning у локальній збірці. Вони не є твердженням про успішну перевірку майбутньої major-версії.

GitHub CI запускається для коміту з цією зміною. На момент запису його результат ще невідомий; фактичний статус перевіряється в Actions для конкретного SHA, а не вважається успішним за наявністю YAML.

Немає нових міграцій, платних ресурсів, хмарних env-змін або переписування Git history. Звичайний push dev може запустити налаштовані CI/Render/Vercel; окреме примусове production promotion не є частиною C0.4.
