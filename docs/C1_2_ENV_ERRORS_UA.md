# Coffeo C1.2 — конфігурація, помилки та збої БД

API перевіряє `DATABASE_URL`, `PORT`, ключі JWT/cookie та `INTERNAL_API_KEY` перед прийманням запитів. У production внутрішній ключ обов'язковий. Помилка конфігурації називає тільки **поле**, ніколи його значення. БД і схема не змінені; міграції немає.

Відповідь помилки має `error.code`, безпечне `message`, `fieldErrors` і `requestId`. Legacy-клієнти додатково отримують старе верхньорівневе `message`; `/v1/*` лишається суворим до v1-схеми. Валідація — 400, відсутня/неправильна сесія — 401, заборона — 403, відсутній ресурс — 404, конфлікт — 409, ліміт — 429, недоступна БД/провайдер — 503 із `Retry-After: 5`. Неочікувана помилка — 500 без тексту драйвера. `x-request-id` у відповіді відповідає `error.requestId`; вхідний ID використовується тільки якщо відповідає обмеженому формату.

При несправності БД шляхи `/auth/me`, `/auth/refresh`, middleware відновлення access і `/auth/logout` повертають 503. Вони не очищають cookie як при невалідному refresh. Це не вводить новий протокол сесій: `sid/jti`, атомарна ротація та гонки вкладок залишаються C1.3.

Стандартні Fastify request-логи вимкнено, щоб query або заголовки не з'являлися в логах. Наш журнал містить лише метод, шаблон маршруту, статус, тривалість і request ID. Прибрані raw error/payload логи з product/cart/order і відповіді Нової пошти. Жоден токен, cookie, контакт, raw SQL чи env-значення не передається в нові записи журналу.

Синтетичні тести `tests/c1-2-errors.test.cjs` ін'єктують збій БД без реального з'єднання й перевіряють 503, відсутність `Set-Cookie`, безпечне повідомлення та відмінність від 401. Повний `npm test` у CI працює з одноразовою PostgreSQL. API v1 OpenAPI-схема не змінена; контрольна сума C1.1 лишається чинною.
